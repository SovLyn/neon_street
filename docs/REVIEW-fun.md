# 趣味性评审 · Neon Street

> 评审对象：线上版 <https://sovlyn.github.io/neon_street/>（commit `4029155`）
> 方法：1440×900 Chromium 实际操作约 20 分钟；对照 Rust/WASM 与 TS 源码；用 Playwright 取数（FPS、draw calls、拾取命中率、事件投影）。
> 用途：给下一位接手的 agent 做“做不做、先做哪个”的决策依据。**这不是任务书，不构成实现授权。**
> 结论只对“有趣”这个目标负责；工程正确性和任务书合规性另算。

---

## 一句话结论

完成度和“好看”都在线，但**“有趣”目前是“看”的有趣，不是“玩”的有趣**。它更像一个精致的城市沙盘 + 一块很帅的仪表盘：第一眼有氛围，三分钟后没有下一个动作。

最值得做的不是再加功能，而是把已经做出来的东西**让人看见**：默认机位、首屏 HUD、彩蛋可见性、地面霓虹倒影。这四件的性价比远高于新增系统。

---

## 决策速览

影响 = 对“有趣”的提升；成本 = 一个熟练 agent 的工作量；风险 = 回归/性能/范围风险。
“MISSION”列标注是否越过任务书边界。

| 3 | 交互 hover 提示 + 效果留痕 | 高 | 1 天 | 中（“瞬时反馈”是任务书原文） | **需确认** |

## 逐项说明

### 1. 默认机位是“远景沙盘”，不是“霓虹街”

**现象**
- 相机在 `(40, 9.5, 42)`，看向 `(-2, 7.5, -4)`（`web/src/scene/index.ts:102`）。
- 画面底部约 1/4 是几乎全黑的水面；路口缩在画面中央；招牌字在 1440 宽下只有十几像素。
- HUD 宽 406px（`web/src/ui/ui.css:150`），占 1440 画面的 28%，压住左侧近景。

**为什么影响“有趣”**
第一眼看到的不是“霓虹街区”，是“控制台 + 一块远景”。用户要先理解这个作品，才可能觉得它有趣；现在理解成本花在了 UI 上。

**建议**
- 机位降到 5–8m 高、距路口 30–35m，让最近的招牌占画面 1/5 左右。
- 水面前景保留，但压到画面 10–15%；不要让它成为最大的一块暗部。
- 可以给两个 home 机位（近景街口 / 远景沙盘），默认近景，“重置机位”在两者间切换。

**验收**
- 1440×900 首屏截图中，至少 3 块招牌的文字可辨认；
- 水面占屏 < 20%；
- 不需要拖动相机就能看出“这是霓虹街”。

**成本/风险**：0.5 天；低。只改常量，但会影响所有预设、摄影模式和截图基线，需一起回归。

### 2. HUD 把最能“玩”的东西藏到了屏幕外（bug 级）

**现象**
- dock：`bottom: 24px; max-height: min(72vh, 620px); overflow: auto`（`web/src/ui/ui.css:146`）。
- 1440×900 下 dock 从 y≈256 到 876；“进入摄影模式”按钮在 y≈883，“分享链接”在 y≈933——**都在首屏之外**。
- 首屏可见的只有时间、天气、配色的滑杆；换街、分享、触发异常、画质、摄影全在折叠区或滚动区下方。
- 滚动条是 `scrollbar-width: thin`，视觉上几乎不存在，用户不知道下面还有东西。

**为什么影响“有趣”**
作品 80% 的“玩点”在首屏不可见。用户不会去找。

**建议**
- 首屏只保留：时间、天气、配色。
- 把 换街 / 分享 / 摄影 / 触发异常 做成底部固定工具条，或右上角一排图标（带 tooltip）。
- 折叠区只放参数（预设、画质、seed 输入）。
- 不需要重做视觉语言，沿用现有样式即可。

**验收**
- 1440×900 与 1280×720 下，换街、分享、摄影、异常四个动作无需滚动即可点击；
- dock 高度不超过视口 60%；
- 现有 e2e 的 `data-testid` 全部保留。

**成本/风险**：0.5–1 天；低。会动 `web/src/ui/index.ts` 的结构和 `ui.css`，注意别破坏 photo mode 的 scoped 规则。

### 3. 交互没有“钩子”

**现象**
- 在 1440×900 首屏按 25px 网格采样约 1100 个点，只有 95 个能命中招牌/路灯/水面，约 **9%**。
- 光标始终是十字；hover 没有任何高亮或文字提示（`web/src/main.ts:174` 起是纯 click raycast）。
- 点完只有 0.18s 白闪 + 一句 toast；招牌 glitch 会衰减回原样，路灯可以再点开，水面涟漪 < 1s。
- 没有任何计数、组合或“再点一次会怎样”的预期。

**为什么影响“有趣”**
这是“玩具”与“模型”的分界线。现在它奖励不了一次重复动作。

**建议（按侵入性从低到高）**
1. hover 时给目标加描边/提亮，cursor 变 pointer，并在 cursor 旁显示招牌文字或“路灯”标签。
2. 让效果留痕一小段时间：招牌保持半坏 3–5s、路灯熄灭后该段路明显变暗、涟漪扩散后漂来一只纸船（程序化几何即可）。
3. 两个轻组合：连点 3 盏灯 → 整条街闪一下；点水面 5 次 → 一条船驶过。不做计分、不做胜负。

**注意**
MISSION 第四节写的是“三条，均为瞬时反馈，不做规则和胜负”。第 1 条是纯 UI 增强，合规；第 2、3 条把“瞬时”延长成了“短暂状态”，**属于对任务书的偏离，必须先问项目所有者**。如果只批准一条，做 hover。

**验收**
- 鼠标移到可交互物上，100ms 内出现可见反馈；
- 离开后恢复；
- 触摸/点击路径不受影响；
- 不掉帧（hover raycast 可 100ms 节流）。

**成本/风险**：hover 0.5 天；留痕/组合 1–1.5 天；中风险在“状态清理”，别让临时状态泄漏到 URL 或 reseed。

### 4. 彩蛋基本看不见（实现 bug，不是设计问题）

**现象**
- 自动事件间隔 45–120s，最多同时 2 个（`src/core/events.rs:32,65`），无声音、无提示。
- 猫：`x = dir * (-65 + 130p)`，duration 4s（`src/core/events.rs:93` + `duration` 表）→ **32.5 m/s**，身高 0.5m。它不是“窜过街”，是横穿 130m 世界。
- UFO / 流星：`y` 在 34–48m（`src/core/events.rs:51`），默认机位朝向路口，经常直接出画。实测一次事件起点投影到屏幕外 3400px。
- 整街闪一下（kind 2）是唯一“一定能感知”的事件，但它只闪所有招牌，没有别的表达。

**为什么影响“有趣”**
彩蛋的价值 100% 来自“被看到”。现在等于没有。

**建议**
- 猫：改成在路口附近横穿 12–18m，速度 6–8 m/s，duration 2–3s；高度抬到 0.3m 以上，别贴地。
- UFO：高度降到 18–26m，路径穿过默认视野中心；加一束很淡的扫描光或底部灯，让它“值得抬头”。
- 流星：固定在天空可见区域（可用相机视锥投影校验），持续 1.5s 左右。
- 频率：20–40s 一次；同一时间最多 1 个，避免互相盖住。
- 提示：在 brand 卡片底部滚一行事件日志（`23:14 · 有猫穿过路口`），或极轻的镜头偏移 0.2s。不做音效（任务书排除）。
- “触发异常”按钮现在随机，改成从 4 种里选，方便演示和测试。

**验收**
- 默认机位下，四种事件各有 ≥80% 的持续时长在视口内（可用 Playwright 投影断言）；
- 猫的横穿距离 < 25m、速度 < 9 m/s；
- 事件发生时，DOM 中 300ms 内出现一条可见提示；
- 连续观察 2 分钟至少能看到 2 次事件。

**成本/风险**：0.5 天；低。纯 Rust 参数 + 一条 UI 日志。注意别破坏 `events_json` 的契约。

### 5. 招牌太小，霓虹读不出来

**现象**
- 20 块招牌大多是 1.4–2.2m 高的横向牌；512×192 纹理上的字在默认距离只有十几像素。
- 横向/竖向/天台/blade 四种类型按 id 轮转，尺寸随机但整体偏小。
- bloom 阈值较低，近景灯头是白色球，糊成一坨；招牌的光晕平面是矩形，远看像雾块。

**建议**
- 选 4–6 块“hero sign”：宽 10–16m，放在默认机位正对的两三栋楼上；字体更大、对比更强。
- 其余招牌作为背景层，允许小。
- 灯头染主题色、降低核心亮度；光晕用径向渐变而不是矩形平面。
- 摄影模式可以加“聚焦招牌”的预设机位。

**验收**
- 首屏至少 3 块招牌文字可读（不需要放大）；
- hero sign 在 1280 宽下仍可读；
- 没有新的全屏白块。

**成本/风险**：0.5–1 天；低。会碰 `src/core/layout.rs:316` 附近的招牌生成和 `web/src/scene` 的招牌材质。

### 6. 湿路面几乎不反光（最可惜的一项）

**现象**
- planar reflection 同时服务于东南角水面和路面湿片，但路面湿片的权重被 `grazing = pow(1 - V.y, 3.2)` 压得很低（`web/src/scene/index.ts:67`）。
- 湿片还乘了 `wet`（默认约 0.4）和 puddle 遮罩，最终 alpha 常在 0.1 以下。
- 截图里路面基本是哑光黑，只有零星高光；霓虹没有在地面形成任何拖影。

**为什么影响“有趣”**
霓虹倒影是这类作品最抓人的视觉符号。现在最弱的一环恰好是“霓虹街”的核心。

**建议（便宜的假反射，不增加反射 pass）**
- 每块招牌在地面放一条朝相机方向、上下翻转、纵向拉伸 6–10m 的 additive 平面，贴同一张招牌纹理，alpha 0.08–0.18，随距离衰减。相机移动时按视角做轻微偏移即可。
- 车尾灯在地面加一条红色拖尾 quad；路灯加一小片椭圆光斑。
- 保留现有真反射给水面；不要把 planar reflection 扩到整条街（成本翻倍）。

**验收**
- 夜景首屏中，至少 5 块招牌在地面有可见的彩色拖影；
- 新增 draw call < 120；
- 反射关闭时这些拖影也应关闭（跟随 `reflections` 开关）；
- 低画质档下可整体禁用。

**成本/风险**：1 天；中。主要风险是 overdraw 和“拖影穿模”，需要按人行道/路面高度做 clamp。

### 7. 白天像黑色纸盒

**现象**
- `renderer.shadowMap.enabled = false`（`web/src/main.ts:76`），全场无阴影。
- 正午窗仍亮（`windowLit = 0.25 + 0.6 * night`，白天 0.25），路灯锥仍开（`0.25 + night * 0.75` 的残余）。
- 车是纯黑箱体，行人是粉色胶囊 + 多面体头；白天没有轮廓光，读作砖块和路桩。

**建议（二选一，不要全做）**
- A. 保留白天但修：白天把窗光和路灯锥降到 0；给建筑/车/人加接触阴影（地面径向渐变 decal 或低分辨率 shadow map）；车加窗带和车灯，行人加两条腿和伞的轮廓光。
- B. 弱化白天：默认和预设压在黄昏/夜晚，正午作为次要模式，只保证不崩。

从“有趣”看，B 的性价比更高；从任务书“昼夜联动”看，A 更完整。建议先 B，时间允许再 A。

**验收**
- 正午截图里建筑立面不是纯黑，窗不发光，路灯锥不可见；
- 车辆和行人在 30m 内能区分；
- 切换时间无闪烁/材质跳变。

**成本/风险**：A 1–1.5 天，B 0.5 天；中。shadow map 会影响集显帧率，需配合第 9 项。

### 8. “换一条街”名不副实

**现象**
- seed 只影响楼的宽高、颜色、窗灯、招牌尺寸、灯高。
- 招牌文字、字体、类型序列来自固定数组 + `id`（`src/core/layout.rs:316–370`）；每条街都是同样的 20 块招牌、同样的 14 个词、同样的顺序。
- 路灯 28 盏位置固定；街具、船、运河、码头、机位全部固定；布局永远是“三象限楼 + 东南水”。
- 按 3–5 次就能预判下一条街。

**建议（按性价比排序）**
1. 招牌词库、字体、类型、色板由 seed 抽取（不是 id）——半天，立竿见影。
2. 街具种类/数量/位置由 seed 决定（摊车、自动贩卖机、自行车、垃圾袋、雨棚）。
3. 布局变体：运河在东南 / 天桥横跨 / 高架穿过，三选一；建筑网格在象限内做 1–2 个空地和窄巷。
4. 机位随布局微调，让每条街的“明信片角度”不同。
5. 给每条街一个可描述的“性格”（食街/电器街/住宅区），用它约束词库和道具。

**验收**
- 连续换 5 条街，招牌文字集合和街具组合至少有 3 条明显不同；
- 至少 2 种布局变体；
- 分享 URL 能恢复同样的街；
- 现有 Rust 测试（`cargo test`）全绿。

**成本/风险**：1.5–2 天；中。会动 `layout.rs` 的序列化和前端假设（招牌数量不固定），需要同步 CONTRACT 和测试。

### 9. 自适应画质

**现象**
- 实测 1089 draw calls / 44,205 triangles，测试机 1600×1000 下 212–240 FPS。
- 但这是单机数据；bloom + planar reflection + 2200 条雨线在集显上可能直接掉到 20。
- 画质只有手动开关，没有自动降级；HUD 的 FPS 在 240Hz 屏上显示 240，参考价值低。

**建议**
- 连续 3s < 40 FPS：先关反射，再关 bloom，再降 DPR 到 1（最多降一档，不要无限降）。
- 给一次 toast：“已自动降低画质，可在‘画质’里恢复”。
- 不要自动改用户手动设置的档位；手动设置后 30s 内不自动降。

**验收**
- 用 CDP 把 CPU 降速 6×，页面仍能保持 >25 FPS 且不崩；
- 自动降级只发生一次，且可恢复；
- 不改变默认画质下的截图。

**成本/风险**：0.5 天；低。注意别和 photo mode 的暂停逻辑打架。

### 10. 自定义招牌文字（P1，最强分享钩子）

**现状**：TODO P1 已列；任务书选做。当前招牌文字完全由 id 决定，无法输入。

**为什么值得**
这是唯一能让用户“留下自己东西”的功能：输入名字/梗 → 楼顶大招牌 → URL 带文字 → 截图发人。传播价值高于再加一个天气。

**建议**
- 输入限 8 个字符（中英混排），选一块 hero sign 应用；不要做“选中任意招牌”（交互成本高）。
- 文字进 URL（`sign=`），同时影响截图水印和分享卡片。
- 字体仍用 canvas 程序化绘制，不引外部字体；对 CJK 做 fallback。
- 空输入时回到 seed 生成的文字。

**验收**
- 输入 → 招牌 200ms 内更新；
- 刷新/分享链接后文字一致；
- 8 字符内不溢出、不缩小到不可读；
- 清空后恢复默认。

**成本/风险**：1.5–2 天；中。需要动 Rust 的 layout JSON 或前端覆盖层，注意 URL 长度和 XSS（canvas 绘制，风险低）。

### 11. 视觉回归测试

**现象**：现有 e2e 覆盖初始化、时间、主题、交互、URL、canvas 有输出；但没有像素级基线。这个项目的主要风险是“看起来坏了”，而当前测试对“看起来”几乎不敏感。

**建议**
- 固定 seed + 时间 + 主题 + 关闭自动循环，截 3 张：默认夜景、正午、摄影模式。
- 用 `toHaveScreenshot`，阈值放宽（maxDiffPixelRatio 0.02），只防止“黑屏/全白/UI 错位”。
- CI 里跑 headless Chromium，固定 DPR=1、字体。

**验收**：故意改坏一个材质，测试能红；正常改动可通过。

**成本/风险**：0.5 天；低。跨平台字体差异可能导致 flaky，阈值要松。

### 12. 手机端提示（超范围，仅建议）

**现象**：390px 视口下 HUD 占了大半屏，场景几乎不可见；任务书明确“不做移动端适配”。

**建议**：只加一条一次性提示——“本作品为桌面体验，建议 1280px 以上宽度”，并提供“隐藏 HUD 预览”。不做布局适配、不做触控优化。

**成本/风险**：0.5 小时；极低。属于范围外的小礼貌，需所有者点头。

---

### 13. 音效（明确不做）

任务书把“音效/音频”写进了“明确不做”。从“有趣”角度，这是最大的天花板：雨声、远处车流、霓虹电流、点击轻响，比再加三个 3D 功能都值。

**建议**：不要在未重新定义产品边界的情况下实现。把它作为“如果允许改任务书”的第一提案，交给所有者决策。

---

## 明确不建议做

- **不要把 planar reflection 扩到整条街。** 现在是单平面 512²，扩到路面会让 draw call 翻倍，收益不如第 6 项的假拖影。
- **不要加第一人称/自由飞行。** 任务书排除，且会暴露低模近景。
- **不要为了“有趣”加计分、任务、胜负。** 任务书明确不做规则；会把这个作品变成半成品游戏。
- **不要重写渲染架构或换 three 版本。** 当前工程边界是资产，不是负债。
- **不要用外部 CDN 字体/贴图解决招牌可读性。** 违反资产策略，且离线构建会挂。
- **不要在没有截图基线时大改 bloom 参数。** 很容易把夜景调成灰雾。

---

## 建议顺序

**第一刀（0.5–1 天，纯收益）**
1. 默认机位 + 水面占比（第 1 项）
2. 彩蛋参数修正 + 事件日志（第 4 项）

这两项不改架构，先把“第一眼”和“前三分钟”救回来。

**第二刀（1–2 天，提升“玩”）**
3. HUD 重排（第 2 项）
4. hover 提示（第 3 项的第 1 条，合规部分）
5. hero sign（第 5 项）

**第三刀（2–3 天，提升“想截图”）**
6. 假霓虹倒影（第 6 项）
7. 白天修正 B 方案（第 7 项）
8. 换街的 seed 多样性（第 8 项第 1–2 条）

**之后**：自定义招牌（第 10 项）、视觉回归（第 11 项）、自适应画质（第 9 项）。
